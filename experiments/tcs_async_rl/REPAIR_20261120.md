# Inference repair: writable AMD kernel cache

The first group diagnostic failed before model generation. This is an operational repair under the user's standing approval.
The scientific question, model revision, question, rubric, thinking mode, samples, seeds, and token limits remain unchanged.

## Failure evidence

- Original Slurm job: 530287. State FAILED, exit 1:0, elapsed 03:29:06.
- Qwen responses: zero. There are no group reward measurements. Missing generation is not a zero score.
- Container pull/conversion: 11,949 seconds. Sandbox extraction: 565 seconds.
  Model cache check: 16 seconds. The inference process failed after about 15 seconds.
- Exact failure: `OSError: [Errno 30] Read-only file system: '/home1'`.
- Call path: SGLang engine import → AITER import → `get_user_jit_dir()` → fallback to `~/.aiter`.
- The launcher mounted the work filesystem with `--no-home`, but did not supply AITER's explicit cache override.
  Its XDG, Triton, and Torch cache settings do not control AITER's fallback.
- The container's AITER source checks `AITER_JIT_DIR` before inspecting or copying into the home directory.
- GPU discovery and tokenizer formatting worked: MI350X, 288 GiB device memory, 374 prompt tokens.
  The job's utilization report recorded zero compute utilization. No model engine was initialized.
- Raw v1 logs were preserved and uploaded to the private `miles/group-check-v1` artifact directory.

## Exact repair

Set `AITER_JIT_DIR` to a writable directory under the already-bound work cache, separated by container image name.
Keep the container home unmounted. Do not copy credentials or change HOME.
Add an engine-import stage before the model download/cache check, so import failures surface before model initialization.
Reuse the downloaded image, extracted sandbox, and pinned model weights.

The immutable original config remains `group_check_v1.json`. The replacement is `group_check_v2.json`.
Only its job identity, repair metadata, cache environment, and import preflight differ.
The replacement uses a fresh source worktree and result directory, one MI350 GPU, and the same four-hour upper bound.
